# derminal

## 研究依据

- [Termux](https://github.com/termux/termux-app)：复用其终端模拟器、原生 PTY 和 Canvas 渲染。源代码固定在 `8629e632fcb95da272221be327db653fb24befe9`，保留 Apache 2.0 许可。支持 VT/ANSI、256 色和真彩色、Unicode、选择复制、鼠标报告、备用屏幕、括号粘贴和终端窗口尺寸更新。
- [Termux 功能键配置](https://wiki.termux.com/wiki/Touch_Keyboard)：采用可锁定的修饰键、方向键长按连发和双行排列。没有重新实现终端转义序列；优先使用终端核心的模式感知按键映射。
- [PRoot](https://github.com/termux/proot)：用户空间文件系统映射和用户身份模拟，无需 root。使用 Termux 版本的 Android 兼容补丁和 seccomp 优化。提供关闭加速的兼容设置。
- [Debian 13 Trixie](https://www.debian.org/releases/trixie/)：当前稳定版本，内置镜像已更新至 13.7 和构建时可用的安全更新。底包来自固定 SHA256 的 proot-distro 发行文件。
- [Android 应用数据执行限制](https://developer.android.com/about/versions/10/behavior-changes-10)：采用 compileSdk 36、targetSdk 28，以支持用户安装的 Linux 可执行文件。这是直接安装版的运行约束。Android 可能显示旧目标版本提示。
- [Android 前台服务](https://developer.android.com/develop/background-work/services/fgs/service-types)：会话由前台服务保留，提供常驻通知和可选唤醒锁。后台运行仍受系统进程限制和厂商电池策略影响。

## 界面和交互

界面由 Compose 构建。默认纸白配色，标签栏和按键区使用紧凑、统一的黑白灰控件。终端内容由专门的 Canvas View 绘制，通过 AndroidView 集成。

- 打开即为终端，首次使用自动校验并展开离线镜像。过程具备磁盘容量检查、进度、错误与重试，采用临时目录和原子重命名，避免留下半安装状态。
- 顶部横向标签，长按改名，关闭均确认。未读输出标记、退出状态和重新打开入口。最多 12 个会话，共享同一 Debian 文件系统。
- 功能键固定两行，最右为设置键和键盘键。Ctrl、Alt、Shift、Fn 轻点作用一次，长按锁定。箭头、删除和翻页键支持长按连发。可修改每行 4–9 键，支持 F1–F12 和常见符号。
- 设置弹窗有外观、输入、会话、系统四个分区，入口固定，仅当前分区内容滚动。
- 外观包括四套完整 ANSI 配色、自定义前景和背景色、字号、字体导入、字重、背景图、遮罩和光标样式。
- 会话包括搜索及文本导出、选择复制、粘贴多行确认、显示重置、启动目录和命令、滚动缓冲、常亮和唤醒锁。
- 系统包括文件选择器导入到 `/shared`、手机存储授权、通知、兼容开关、日志导出和设置恢复。

## 性能与可靠性

PTY I/O 在线程中处理，终端输出只通知当前 View，并按显示帧合并刷新，不将输出逐行转成 Compose 状态。非选中标签只更新未读标记。根文件系统所有会话共享，避免重复复制数百 MB 的系统文件。终端滚动区有固定上限。背景图导入时采样到约 2200 像素以内，不逐帧解码。镜像校验和展开、文件导入、诊断导出在 IO 线程执行。

PRoot 使用 ptrace，性能无法等同原生 chroot，特别是大量小文件系统调用。默认使用可用的 seccomp 加速。应用不承诺绕过 Android 的 phantom process 和电池限制。

标签元数据持久保存。应用进程死亡后恢复标签并重新打开 shell，显示恢复提示；不会声称还原已经终止的进程，也不重放历史命令。终端命令、输出、剪贴板和环境变量不写入诊断日志。日志在本地轮转，总大小约 512 KB。

## 发布验证

Actions 在 GitHub 托管的 Ubuntu runner 制作离线系统镜像并更新 Debian 软件包，用 NDK 编译 PTY，执行终端核心及输入映射单元测试、Android Lint、R8 和签名构建。系统镜像、第三方对应源代码和 APK 均在云端制作。Release 提供 APK、SHA256、签名信息、混淆映射、构建来源和第三方源代码。

编译与自动化检查不能替代真机视觉和交互验收。未使用模拟器进行 UI 验收。首发需在用户设备重点检查中文输入法、横竖屏、系统返回、粘贴选择、功能键和后台任务。
